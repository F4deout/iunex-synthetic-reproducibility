# E4 tolerance k=20 information ablation: analysis plan

Status: fixed **before ablation model results**; 2026-09-21. The locked E4 Phase 1 outcome is known. This is a read-only, explanatory follow-up, not an independent preregistered confirmation. The generator, parameter, workload grid, history schema and all existing artifacts remain unchanged. Five seeds 110/220/330/440/550, frozen 72/24/24 subject folds, E4 test keys, log-time Ridge, alpha grid 1/10/100, validation MAE selection, train-only imputation/standardization, and minute-scale ID-test MAE are identical to the locked tolerance protocol. Each condition is refit independently. Positive `MAE(condition)-MAE(full)` means removing information hurts. Five-seed paired mean/SD/t(df=4) 95% CI and per-seed directions are reported.

All conditions contain pre-E4 `v5_kmh` and `evaluation_order`. No current E4 HR, actual time, completion flag, stop time, latent state or target enters a predictor. The canonical k=20 features are calculated from the same twenty **calibration** events. Conditions are fixed as follows:

1. `k0_v5`: only the two baseline fields; must exactly reproduce frozen k=0.
2. `full_k20`: all frozen k=20 fields; must exactly reproduce frozen full result.
3. `no_stop_time`: drop `median_observed_stop_minutes`, `cs_pair_candidate_mps`, `dprime_pair_candidate_m`, `cs_pair_valid`, all F/S `*_lead_actual_minutes` and `*_probe_stop_minutes`, and `fast_stop_vs_log_gap_slope`. Keep completion indicators; this removes numeric observed stop times and their explicit derived inversions, including rare censored lead times.
4. `no_F_source`: start from the twenty calibration events, mask **all six F1/F2/F3 lead/probe events**, and rerun the unchanged history-feature function on the remaining events. This removes F information from explicit F columns *and* pooled stop-time/HR/completion aggregates. The feature schema is unchanged; `n_events=14` is a condition constant.
5. `no_G5G6_source`: similarly mask the two G5/G6 events before the unchanged history-feature function. This removes their explicit CS/D′ pair and contributions to pooled summaries. `n_events=18` is a condition constant.
6. `no_completion_flags`: drop `n_completed`, `n_stopped`, `max_completed_planned_minutes`, `max_completed_speed_kmh`, `mean_stopped_speed_kmh`, `cs_pair_valid`, all F/S `*_pair_valid`, `*_lead_completed`, `*_probe_completed`. Numeric stop times remain. Their presence/null pattern still implies some completion information, so this is a **marginal explicit-flag ablation**, not total removal of event status.
7. `no_recovery_context`: drop all F/S `*_pair_valid`, `*_lead_actual_minutes`, `*_lead_completed`, `*_probe_completed`, `*_probe_hr_minus_lead_hr`, `fast_pair_count`, `slow_pair_count`, `fast_stop_vs_log_gap_slope`, `slow_hr_vs_log_gap_slope`, `last_gap_h`, `mean_gap_h`. Keep F/S observed probe stop times and pooled stop-time summaries so this isolates recovery timing/contrast context **conditional on tolerance measurements**.
8. `no_HR_response`: drop `rest_hr_mean`, `rest_hr_last`, `hr_speed_slope`, `hr_speed_intercept`, `hr_speed_resid_sd`, `observed_hr_count`, `hr_quality_count` and all F/S `*_probe_hr_minus_lead_hr`. Keep performance and gap fields.
9. `minimal_tolerance`: use only baseline fields plus `cs_pair_candidate_mps`, `dprime_pair_candidate_m`, `cs_pair_valid` from the unchanged k=20 history. This is a two-observed-stop inverse proxy; no F stop times or HR are included.

These groups overlap because the frozen feature engineering pools source events. Their ablation losses are **conditional model-retraining effects, not additive causal shares**. Source-masked F/G conditions are stronger than dropping named columns and may also remove their HR/completion information; interpret accordingly. Do not alter or add features after results. Save raw predictions, per-seed metrics, exact retained/removed names, source-event masking, frozen hashes and validation assertions in a separate artifact directory. Check frozen full/k0 predictions and keys before interpreting ablations. No target or latent oracle is part of this audit.
