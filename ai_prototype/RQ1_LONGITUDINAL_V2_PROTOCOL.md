# RQ1 longitudinal personalization v2 preregistration protocol

## 1. 연구 질문

실제 경과시간과 활동 맥락이 기록된 종단 합성환경에서, 현재 생체정보에 개인의 과거 센서반응과 자기보고를 추가하면 새로운 세션의 자기보고 상태점수 예측이 단순 개인 기준모형보다 개선되는지를 평가한다.

하위 질문은 다음과 같다.

1. 개인 이력의 추가 예측가치가 현재 센서만 사용한 모형과 단순 자기보고 기준모형을 모두 초과하는가?
2. 추가 가치가 과거 자기보고의 개인별 보고경향 복원과 생리반응 변화 추적 중 어디에서 발생하는가?
3. 기록 수 증가에 따른 변화가 개선 지속, 포화 또는 악화 중 어느 형태인가?
4. 같은 기록 수라도 경과기간과 활동조건별 기록 구성이 다를 때 결과가 달라지는가?

## 2. 기존 결과와의 관계

- v1 종단 DB와 실험결과는 변경하지 않고 방법론적 감사 사례로 보존한다.
- v1의 50~75건 결과는 v2 가설이나 기대값으로 사용하지 않는다.
- v2 parameter와 판정기준은 결과 생성 전에 hash로 동결한다.
- 합성 자기보고 점수는 질환, 임무수행능력, 의학적 readiness 또는 실제 장병의 임상상태 정답이 아니다.

## 3. 데이터 구조

### 3.1 대상자와 분할

- seed별 합성인원 120명
- train 72명 / validation 24명 / ID-test 24명
- 대상자 ID 교집합 0
- 동일 대상자의 세션 및 파생표본은 하나의 split에만 배치
- final seed 110, 220, 330, 440, 550

### 3.2 실제 경과시간

- 각 대상자의 관측은 고정 회차가 아니라 `calendar_day`와 `measured_at`을 가진다.
- 관측 간격은 LOW/BASE/HIGH 시나리오별 사전고정 분포에서 생성한다.
- 이력에는 기록 수와 함께 첫 기록 이후 경과일, 최근 기록 이후 경과일 및 이력창의 총 기간을 보존한다.
- 같은 k라도 실제 포함 기간이 다를 수 있으며 k를 실제 일수로 해석하지 않는다.

### 3.3 활동 맥락

- 측정 상황: 안정 시, 활동 직후, 회복 중
- 활동 종류: 유산소 운동, 하중을 수반한 이동, 맨몸 순환운동, 활동 없음
- 관측 가능 정보: 활동 종류, 외부 운동부하, 계획·실제 지속시간, 완료·중단, 회복간격
- 활동 이름은 합성 과업 범주이며 실제 군 표준검사로 해석하지 않는다.

## 4. 생성구조

### 4.1 공통원인 구조

`개인 특성 + 시간에 따라 변하는 수행능력 + 이전 상태 + 활동조건 + 환경 + 비관측 요인`

→ `현재 잠재 생리상태`

→ `true physiology`

→ `센서별 측정과정`

→ `관측 HR·체온·SpO₂·선택적 땀 젖산`

동시에

`현재 잠재 생리상태 + 현재 비관측 상태요인`

→ `noiseless subjective state`

→ `시간에 따라 변하는 보고과정 + 독립 보고오차`

→ `관측 자기보고 점수`

센서 관측값으로 정답을 직접 생성하거나 정답으로 센서값을 직접 생성하지 않는다.

### 4.2 수행능력 변화

- 개인별 수행능력은 연속적인 완만한 변화와 드문 변화사건으로 구성한다.
- 변화사건 시점은 대상자별로 독립적으로 생성하며 train/validation/test 평가창과 정렬하지 않는다.
- 향상·안정·저하의 방향과 크기는 결과와 무관하게 사전고정 시나리오에서 생성한다.
- 현재 수행능력은 predictor에 제공하지 않는 audit-only latent이다.

### 4.3 자기보고 과정

- 개인별 보고수준 차이, 시간에 따른 완만한 이동, 드문 기준변화 및 세션별 독립오차를 분리한다.
- 기준변화 발생 여부와 시점은 개인별로 독립적이며 평가 시작점과 정렬하지 않는다.
- predictor는 과거에 실제 관측된 자기보고만 사용할 수 있다.
- audit에서는 관측 자기보고와 noiseless subjective state를 별도로 평가하여 보고경향 복원과 상태정보 복원을 구분한다.

## 5. 이력 조건

### 5.1 기록 수

`k = 0, 5, 10, 20, 30, 50, 75, 100`

모든 k에서 동일한 대상자·현재 세션을 평가하고 각 k의 특징생성, 전처리, validation 선택 및 재학습을 독립적으로 수행한다.

### 5.2 이력 정보군

1. 센서 이력만
2. 과거 자기보고만
3. 센서·활동맥락 이력
4. 센서·활동맥락·과거 자기보고 전체 이력

센서 이력은 전체 평균만 사용하지 않고 다음을 포함한다.

- 안정 시 개인 기준선
- 활동 종류·외부부하·지속시간으로 조건화한 심박반응
- 활동 후 체온·SpO₂ 변화
- 회복간격에 따른 회복 관측
- 개인 내 변동
- 최근 기간의 변화 기울기

### 5.3 이력 최신성

- 최근 k건 균등 요약
- 최근 30일 이동창
- 최근 90일 이동창
- 반감기 30일의 지수가중 요약

이 조건은 기록 수 효과와 실제 경과시간 효과를 구분하기 위한 방법 비교이며, 하나가 우수하다고 사전 가정하지 않는다.

## 6. 예측 대상

### 6.1 주 분석

- 관측 현재상태 자기보고 0~10
- 관측 피로 자기보고 0~10
- 활동 세션의 관측 운동부담 자기보고 0~10

### 6.2 audit-only target

- 보고과정 적용 전 noiseless subjective state
- 현재 개인 보고편향
- 현재 수행능력과 활동조건별 생리반응

audit-only target은 predictor 학습 정답이나 실제 시스템 출력으로 사용하지 않는다.

## 7. 사전등록 비교모형

1. train mean baseline
2. 현재 센서 Ridge(k=0)
3. 개인의 마지막 자기보고
4. 개인의 최근 5건 자기보고 평균
5. 개인의 최근 20건 자기보고 평균
6. 반감기 30일 지수가중 자기보고 평균
7. 활동조건별 개인 평균
8. 센서·활동맥락 이력 Ridge
9. 센서·활동맥락·자기보고 이력 Ridge

개인이력 AI의 추가 가치는 k=0뿐 아니라 3~7의 단순 기준모형과도 비교한다. AI가 단순 기준모형을 넘지 못하면 개인화 AI의 추가 가치가 확인되지 않은 것으로 기록한다.

## 8. 학습과 평가

- 전처리 fit: train only
- 모델 선택: validation only
- ID-test: 최종 평가에만 사용
- Ridge alpha: 1, 10, 100
- 지표: MAE, RMSE, R²
- 5개 seed의 mean±SD 및 paired difference 95% CI
- 실제 사람 모집단 CI 또는 통계적 유의성으로 표현하지 않는다.

### 8.1 변화구간 평가

- 변화사건 이전 안정구간
- 변화 직후 구간
- 변화 이후 재안정 구간
- 변화사건이 없는 대상자

각 구간을 별도로 보고하고 전체평균으로 변화 직후의 실패를 숨기지 않는다.

### 8.2 포화 판정

인접 k의 paired MAE 차이를 모두 계산한다.

- `CONTINUED_IMPROVEMENT`: 이후 두 구간 이상에서 0.02점 이상의 개선 방향과 CI 방향이 유지
- `PLATEAU`: 연속 두 구간의 절대 차이가 0.02점 미만이고 CI가 0을 포함하며 이후 뚜렷한 개선·악화 없음
- `DETERIORATION`: 더 긴 이력에서 0.02점 이상의 악화가 발생
- `INCONSISTENT`: seed 또는 구간별 방향 불일치

최적 k 하나를 실제 권장 기록 수로 제시하지 않는다.

## 9. 사전등록 반증시험

1. 학습 target shuffle
2. 개인별 history identity destruction
3. history time-order destruction
4. 과거 자기보고 정보 제거
5. 활동맥락 정보 제거
6. 센서 이력 제거
7. 보고편향을 고정·이동·무편향으로 바꾼 민감도 비교

성능을 개선하는 것이 아니라 모델이 실패해야 할 때 실패하는지 확인한다.

## 10. 누수 통제

- 현재 및 미래 자기보고 입력 금지
- 현재 및 미래 센서기록을 history에서 차단
- latent 수행능력·잠재상태·현재 보고편향 입력 금지
- 전체자료 전처리 금지
- 대상자 split 이후 특징계산
- 변화사건 시점과 평가창의 독립성 assertion
- 동일 현재 평가세션을 모든 k와 비교모형에 사용

## 11. 성공·실패 판정

### `EVIDENCE_OF_ADDITIONAL_HISTORY_VALUE`

- 전체 이력모형이 k=0과 사전등록 단순 개인 기준모형을 모두 개선
- history identity destruction에서 개선 소실
- target shuffle에서 성능 붕괴
- 관측 자기보고뿐 아니라 noiseless subjective state에서도 일부 정보가 유지
- 결과가 하나의 보고편향·변화시점 시나리오에만 의존하지 않음

### `REPORTING_STYLE_RECOVERY_ONLY`

- 관측 자기보고는 개선되지만 noiseless subjective state는 개선되지 않음

### `NO_ADDITIONAL_VALUE`

- 단순 최근값·이동평균·EWMA를 안정적으로 넘지 못함

### `DESIGN_INVALID`

- 누수, 변화시점 정렬, trivial recoverability 또는 반증시험 실패 발견

## 12. 실행 순서

1. parameter register와 sensitivity scenario hash 동결
2. generator 구현
3. dry run과 분할·시간·변화시점 독립성 검사
4. 반증시험
5. `EXPERIMENT_READY` 판정 후 본 실험

현재 단계에서는 generator와 본 실험을 실행하지 않는다.
