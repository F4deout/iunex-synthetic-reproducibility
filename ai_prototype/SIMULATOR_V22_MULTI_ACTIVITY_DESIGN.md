# Simulator v2.2-multi-activity 설계안

상태: **신규 확장 설계; 기존 v2.1 코드·parameter·결과 동결; v2.2 generator 미구현·본 실험 미실행**  
작성일: 2026-09-28  
목적: 국방 의료지원용 상태확인 체계의 활용범위를 러닝 하나로 표현하지 않되, 러닝에서 얻은 결과를 다른 운동에 확대 적용하지 않는 다중활동 구조 설계

## 1. 연구 범위

v2.2는 다음 세 활동군을 별도 모듈로 다룬다.

1. `RUN`: 뜀걸음. 거리·속도·수행시간·완료/중단 기록을 사용한다.
2. `LOADED_MARCH`: 군장 행군. 이동속도·거리·수행시간·군장 무게·경사/지형·완료/중단 기록을 사용한다.
3. `BODYWEIGHT_CIRCUIT`: 맨몸 순환식 체력훈련. 종목·반복 횟수·세트·운동/휴식시간·완료/수정/중단 기록을 사용한다.

세 활동을 하나의 임의적인 “운동강도 점수”로 환산하지 않는다. 활동별 외부 부하의 단위와 생리적 의미가 다르므로 원자료와 활동별 특징을 보존한다. 공통 모델의 역할은 생체정보·개인 기준선·활동 전후 시점·회복 맥락을 공유하는 데 한정한다.

기존 v2.1의 `CS-like`, `D′-like`, reserve 및 exact/observed stop-time 구조는 `RUN` 모듈의 동결된 선행 결과다. 이를 행군이나 순환식 훈련에 자동 승계하지 않는다.

## 2. 공통 정보 흐름

```text
관측 가능한 개인 기준정보 + 활동별 외부 부하 + 직전 활동·회복간격 + 환경
                          ↓
                활동별 잠재 생리상태
                          ↓
          true physiology → measurement process → observed vitals
                          ↓
       activity-specific outcome / independent reporting process
```

센서 관측값이 target을 직접 만들거나 target이 센서값을 직접 만드는 식을 사용하지 않는다. 활동별 잠재상태는 공통 원인이 될 수 있으나, 정답과 관측 생체신호에는 서로 분리된 비관측 요인과 측정/보고 과정을 둔다.

### 공통 observed 입력

- 활동 전·후·회복 시점과 측정조건
- 심박수, SpO₂, 체온 및 향후 장치에서 실제 취득되는 생체정보
- 활동 종류
- 계획·실제 수행시간
- 완료·중단·수정 여부와 관측된 중단시간
- 직전 활동 종료 후 회복간격
- 기온·습도 등 실제로 기록된 환경정보
- 동일인이 과거 동일 또는 유사 조건에서 보인 관측 반응

### predictor에서 금지하는 정보

- 합성 개인의 true capacity와 true reserve
- `CS-like`, `D′-like`, q, strain, debt, recovery time constant
- 현재 또는 미래 target
- 완료 세션의 가상 중단시간
- 생성기 내부 난수와 noiseless target
- ID-test 결과로 선택한 parameter 또는 특징

## 3. 활동별 외부 부하

### 가. RUN

기록 단위는 거리, 실제 수행시간, 평균/구간 속도, 경사, 완료·중단 및 중단시간이다. 배포 가능한 조건 배정은 사전에 관측된 3 km 또는 다른 독립 수행기록을 사용할 수 있으나, 해당 기록을 실제 CS와 동일시하지 않는다. 기존 v2.1의 5 km anchor 결과는 그대로 보존하고 v2.2에서 3 km로 소급 변경하지 않는다.

CS/D′ framework는 러닝의 강도–지속시간 관계를 표현하는 전용 참고틀이다. [Kordi, Menzies & Galbraith (2019)](https://pubmed.ncbi.nlm.nih.gov/30427230/)의 구조적 근거를 사용하되 실제 대상자의 CS/D′ 값으로 간주하지 않는다.

### 나. LOADED_MARCH

행군 외부 부하는 속도 하나가 아니라 이동속도, 수행시간, 군장 무게, 개인 체중, 경사·지형 및 환경의 조합이다. 군장 무게와 이동속도는 생리·역학적 요구를 함께 변화시키며 지형과 환경도 영향을 준다. 이 구조는 군장 보행 연구의 방향적 근거를 따른다([Knapik et al., 2004](https://pubmed.ncbi.nlm.nih.gov/14964502/); [Looney et al., 2018](https://pubmed.ncbi.nlm.nih.gov/30252089/)). 기존 대사비용식을 정답으로 복사하지 않으며, 군 장병에 대한 정확한 계수는 별도 실측 없이는 `UNKNOWN`으로 둔다.

### 다. BODYWEIGHT_CIRCUIT

순환식 훈련의 외부 부하는 종목명, 반복 횟수, 세트, 작업시간, 세트·종목 간 휴식시간, 외부 중량 유무 및 실제 완료량으로 기록한다. 달리기 속도나 CS/D′로 환산하지 않는다. 종목별 기계적 부하와 수행형식이 달라 공통 scalar workload를 만들지 않고, 초기 모델은 활동별 기록 특징과 생리반응을 사용한다.

현재 PMData에는 `Weights` 83건, `Workout` 39건, `Aerobic Workout` 35건, `Circuit Training` 3건이 있으나 세트·반복·종목·휴식 구조가 없다. 따라서 이 자료는 순환식 훈련 parameter 보정자료가 아니며 활동명·지속시간·평균 HR의 지원범위 확인에만 사용할 수 있다.

## 4. 예측 endpoint

### 공통 상태 endpoint

- 활동 후 주관적 운동부담 0–10
- 피로 0–10
- 현재상태 자기보고 0–10

세 정답은 질환, 의학적 readiness 또는 임무수행능력의 대리값이 아니다. 활동별 독립 반복정답이 없으면 합성 가정으로 표시한다.

### 활동별 수행 endpoint

- `RUN`: 관측 중단시간 또는 완료/right-censoring
- `LOADED_MARCH`: 계획구간 완료·중단과 관측 수행시간. 생리적 한계시간과 동일시하지 않음
- `BODYWEIGHT_CIRCUIT`: 계획된 반복·세트의 완료율, 수정/중단 및 관측 수행시간

서로 다른 endpoint의 MAE를 같은 척도로 직접 비교하지 않는다. 관측 중단시간은 all-cause outcome이며 자발적·안전상·행정상 중단 사유를 별도로 기록한다.

## 5. 개인 이력 구조

개인 이력은 두 층으로 분리한다.

1. **공통 이력:** 안정 시 기준선, 활동 전후 생체반응, 회복 시점, 개인 내 변동, 환경 맥락.
2. **활동별 이력:** 같은 활동의 외부 부하, 실제 수행시간, 완료·중단·수정 여부와 중단 사유.

다른 활동의 이력을 옮겨 쓸 때는 공통 기준선·회복반응만 공유하고, 러닝의 중단시간을 행군이나 순환식 훈련의 tolerance 정답처럼 사용하지 않는다. `k=0/1/3/5/10/20` 비교에서는 공통 이력과 활동별 이력을 각각 분리하여 ablation한다.

## 6. 최종 연구 질문

- `RQ-M1`: 독립 기준기록과 공통 생체정보가 주어진 상태에서 동일 활동의 과거 수행이력이 새 세션의 활동별 결과에 추가 정보를 제공하는가?
- `RQ-M2`: 개인의 공통 기준선·생리반응·회복이력은 활동 종류가 달라져도 주관적 상태점수에 추가 정보를 제공하는가?
- `RQ-M3`: 활동별 전용 모델과 활동유형을 명시한 pooled 모델의 정보가치는 지원범위 내에서 어떻게 다른가?

어느 질문도 개인 이력이 항상 성능을 높인다고 전제하지 않는다.

## 7. 자료 근거와 현재 한계

| 항목 | 현재 상태 | 사용 범위 |
|---|---|---|
| PMData 러닝 | 거리·시간·평균 HR·일부 RPE와 5 km anchor 존재 | 기존 v2.1 결과 및 v2.2 RUN의 경험적 참고 |
| 독립 3 km 기록 | 현재 자료에 없음 | `NEEDS_SOURCE`; 실제 수집 전 합성 개인의 실측값처럼 생성 금지 |
| 군장 행군 | 군장 무게·경사·지형·중단 사유가 결합된 현재 자료 없음 | 문헌으로 변수 방향만 제한; 계수는 `UNKNOWN` |
| 순환식 훈련 | 일반 활동명은 있으나 종목·세트·반복·휴식 상세 없음 | 상세 parameter 보정 불가; `NEEDS_SOURCE` |
| 다중센서 | 현재 실제 장치 반복 측정자료 없음 | 센서 오차·결측·artifact는 별도 장치 검증 전 `UNKNOWN` |

## 9. 구현 경계

현재 단계에서 구현 가능한 것은 활동별 원자료를 손실 없이 받는 입력 스키마와 latent 차단 검증기다. 행군·순환식 훈련 generator는 parameter register와 실제/문헌 근거가 잠기기 전 구현하지 않는다. 다음 단계는 `SIMULATOR_V22_MULTI_ACTIVITY_PROTOCOL.md`의 잠금 규칙에 따라 자료지원 감사와 parameter register를 작성하는 것이다.
